# Налаштувати викладення правил доступу — один раз

Правила доступу до бази (`database.rules.json`) — **єдина межа безпеки цього
застосунку**: усе, що робить із базою наш код, може зробити будь-хто тим самим
SDK із консолі браузера. Тому CI викладає їх сам на кожен пуш у `main`, перед
збіркою.

Щоб він міг це робити, потрібен **один секрет**. Доки його немає, прогін не
падає — він пише попередження, а в базі лишаються ті правила, які востаннє
вставили руками.

**Перевірити, чи вже зроблено:**

```bash
gh secret list -R Alik532UA/AudioRemote
```

Якщо у списку є `FIREBASE_SERVICE_ACCOUNT` — усе готово.

Станом на 2026-09-20 його там **немає**: є лише чотири `VITE_FIREBASE_*`.
Тобто джоб `publish-rules` існує й щоразу пропускається.

---

## Крок 1. Дізнатися ідентифікатор бойового проєкту

Він лежить у секреті `VITE_FIREBASE_PROJECT_ID` (значення секрету не показує
ніхто, зокрема й GitHub). Найпростіше подивитися у своєму локальному `.env`
або у Firebase Console — список проєктів на
<https://console.firebase.google.com/>.

У `PROJECT-CONTEXT.md` записано, що бойовий проєкт називається `audioremote`,
а `demo-audioremote` — це **емулятор**, тобто не він.

Далі в командах підставляйте свій ідентифікатор замість `audioremote`.

## Крок 2. Завантажити ключ сервісного акаунта

Сервісний акаунт — «робот», від імені якого CI звертається до Firebase. Ключ
генерує сама Firebase.

1. відкрити
   <https://console.firebase.google.com/project/audioremote/settings/serviceaccounts/adminsdk>
2. натиснути **Generate new private key** («Створити новий закритий ключ»);
3. підтвердити — браузер завантажить файл виду
   `audioremote-firebase-adminsdk-xxxxx.json`.

> Цей файл — **ключ від бази**. Не кладіть його в репозиторій. Після кроку 3
> його можна видалити з «Завантажень».

## Крок 3. Покласти ключ у секрети репозиторію

Одна команда; підставте справжній шлях до завантаженого файлу:

```bash
gh secret set FIREBASE_SERVICE_ACCOUNT -R Alik532UA/AudioRemote < "C:/Users/alik5/Downloads/audioremote-firebase-adminsdk-xxxxx.json"
```

Команда читає файл і відправляє вміст зашифрованим — вставляти текст ключа
руками нікуди не треба.

## Крок 4. Перевірити

```bash
gh secret list -R Alik532UA/AudioRemote
```

Далі будь-який пуш у `main`: у прогоні джоб **publish-rules** має виконати крок
«Викласти правила», а не пропустити його.

```bash
gh run list -R Alik532UA/AudioRemote --limit 1
```

---

## Чому це важить більше, ніж виглядає

У `PROJECT-CONTEXT.md` (§ «Штамп версії правил») записано, що доки правила
живуть лише в емуляторі, питання «чи задеплоєне те, що в git» не стоїть. Щойно
ключ з'явиться, воно постане — і відповідь на нього дає саме цей джоб.

Історія, через яку він написаний: тричі поспіль код починав писати поле, про
яке правило в базі не знало, а `$other: false` відкидає незнане поле разом з
**усім записом**. Дошка тихо переставала оголошуватися, і пульт писав «на
плеєрі ще не обрано папку».

## Якщо крок упав на правах

Типовий ключ Firebase Admin SDK має досить прав. Якщо прийшла відмова
`PERMISSION_DENIED`:

1. <https://console.cloud.google.com/iam-admin/iam?project=audioremote>
2. знайти рядок, що закінчується на `@audioremote.iam.gserviceaccount.com`;
3. олівець → **ADD ANOTHER ROLE** → `Firebase Realtime Database Admin`;
4. **SAVE**.
