## Гейти

Повний перелік із поясненням, що саме кожен стереже, — у PROJECT-CONTEXT § 6.
Мінімум перед комітом:

```bash
npm run check && npm run lint && npx prettier --check src && npm test
```

`npm run check` обовʼязковий саме перед комітом правок розмітки: `npm test`
типів у `.svelte` не бачить.

`prettier --check src` — рівно той крок «Формат», який ганяє CI. Доти його в
цьому мінімумі не було, і п'ять публікацій поспіль упали саме на ньому: усі
гейти локально зелені, типи й браузер у CI теж, а сайт не виїжджав. Лінтер
формату не перевіряє, тож одного `npm run lint` тут недосить.

Повний набір — те саме, що ганяє CI:

```bash
npm run check:runners && npm run check:coverage && npm run check:rules
```

Над збіркою (у Git Bash — саме з `MSYS_NO_PATHCONV=1`, інакше він калічить шлях):

```bash
MSYS_NO_PATHCONV=1 BASE_PATH=/AudioRemote npm run build && npm run check:build && npm run check:bundle
```

```bash
npm run test:e2e
```

## Що спотикає щоразу

- **`check:rules` потребує ЧИСТОГО емулятора.** Він створює дошки з фіксованими
  ключами; на другому прогоні по тій самій базі `ownerUid` лишається від
  першого, і два десятки випадків «мусить уміти» падають із HTTP 401. Це не
  поломка правил. `npm run check:rules` піднімає свій емулятор сам — але лише
  якщо порти 9020/9119/4040 вільні.
- **Емулятор застосовує правила рівно до `{project}-default-rtdb`.** Будь-який
  інший простір імен — порожня база «дозволити все», куди проходить навіть
  запис без автентифікації.
- **Версію піднімає хук `.githooks/pre-commit`**, а не людина. Руками — лише
  `npm version minor|major`.
- **Коміт описує ДЕФЕКТ, а не зміну.** Заголовок — те, що було не так, з погляду
  того, хто цим користується; тіло — чому саме так виправлено, з числами, які
  справді заміряні. Подивіться `git log` — конвенція видно з нього краще, ніж із
  будь-якого опису.
- **Нова перевірка вважається робочою лише після того, як упала** на навмисно
  поверненому дефекті. Результат цього зворотного експерименту — у тілі коміту.
  Не вдалося відтворити дефект — так і написати, а не промовчати.
- **`push` не робити.** Викладання правил у бойову базу й публікація йдуть із
  CI, і ціна помилки тут не косметична (PROJECT-CONTEXT § 6).

## Межі, які не обходяться

- Папку в браузері не запамʼятати між завантаженнями сторінки — це валить
  Chromium, і це заміряно (§ 5.0).
- `showDirectoryPicker()` Playwright не драйвить, тож справжньої папки в e2e
  немає й бути не може.
- Приймач у браузері працює лише в Chrome або Edge на компʼютері.
