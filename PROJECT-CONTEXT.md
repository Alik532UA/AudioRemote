Оновлено: 2026-09-19.

## 1. Що це

Дошка звуків для працівників творчої школи. **Комп'ютер грає, телефон керує.**

Людина відкриває дошку на комп'ютері, який стоїть біля колонок, віддає сторінці
теку з музикою й натискає «Увімкнути звук». Далі будь-хто, кому продиктували
ідентифікатор і пароль, заходить із телефона й запускає треки.

Аудіофайли **нікуди не завантажуються** — вони лишаються на тому комп'ютері.

## 3. Модель безпеки — головне про цей проєкт

**Пароль дошки входить в АДРЕСУ, а не перевіряється правилом.**

Правила Firebase бачать лише `auth` і шлях; передати їм «пароль, який я щойно
ввів» неможливо. Тому дошка живе за `boards/{hex}`, де `hex` — SHA-256 від пари
(ідентифікатор, пароль) — [`src/lib/board/boardPath.ts`](src/lib/board/boardPath.ts).

З цього випливає все інше:

- **Перелічити `boards` не можна** — і саме це тримає конструкцію. Дозвіл читати
  стоїть лише на конкретній дошці; `GET /boards` відкидається.
- У базі **немає ні ідентифікатора, ні пароля**, ні їхніх частин.
- **Зміна пароля = переїзд дошки.** Змінити його на місці неможливо за побудовою.
- **Відкликати доступ окремій людині не можна.** Хто знає пару — той усередині.
- «Немає такої дошки» й «пароль невірний» — **буквально одна відповідь**, і це
  властивість схеми, а не наша обачність.
- Запас тримається на паролі: згенерований дає ≈37 біт
  (`passwordEntropyBits`, поріг під тестом), і перевірити здогад можна лише
  мережевим читанням.

**Господар дошки — КОМП'ЮТЕР, а не людина.** `ownerUid` — анонімний `uid` того
браузера, який дошку створив; там же лежать дескриптори теки. Очищення даних
сайту забирає і те, і те одночасно, тож окремого механізму «не загубити акаунт»
немає навмисно.

## 5. Відомі межі — названі, а не приховані

1. **Приймач — лише Chrome або Edge на десктопі.** File System Access API у
   Firefox і Safari немає. Сторінка це визначає й каже прямо; пульт працює
   будь-де.
2. **Потрібен захищений контекст** (https або localhost). І `crypto.subtle`, і
   дескриптори теки інакше недоступні — тобто відкрити приймач по
   `http://192.168.x.x` не вийде. Для перевірки з телефона: бойова адреса або тунель.
3. **Дозвіл на теку може не пережити перезапуск браузера.** Дескриптор
   переживає, дозвіл — рішення Chrome. Сторінка розрізняє «тека є, треба
   підтвердити» й «теки немає»: перше лікується одним кліком.
4. **Одна дошка — один комп'ютер-плеєр.** Друга машина з тією самою парою зайде
   пультом; бібліотеку й стан пише лише господар.
5. **Фонова вкладка.** Chrome здатен приморозити або скинути фонову вкладку.
   Наскільки це зачіпає приймача — **не заміряно**; це перше, що варто
   перевірити живим прогоном на кілька годин.
6. **Штамп версії правил не зроблений.** Поки правила живуть лише в емуляторі,
   питання «чи задеплоєне те, що в git» не стоїть. Перед першим бойовим
   деплоєм — зробити, як у `VetCrewGames/scripts/rules-stamp.mjs`.

| `BASE_PATH=/AudioRemote npm run build && npm run check:build` | 19 перевірок над `build/`: маніфест під тим самим base, воркер не забирає вкладку, CSP має `media-src blob:`                                                                 |

**Збірку гнати з `BASE_PATH`**, інакше частина перевірок дивиться не туди. У Git
Bash — із `MSYS_NO_PATHCONV=1`, бо він калічить шлях зі скісною рискою.

**Емулятор лишає процес на порті 9020**, коли прогін зупинили. Наступний запуск
скаже про це прямо (`scripts/firebase-cli.mjs` перевіряє порти ДО запуску) —
це не поломка правил.
